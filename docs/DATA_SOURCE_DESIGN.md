# 数据源接口设计

核心原则：上层复盘逻辑永远不要直接依赖某一家数据供应商字段。

## 1. 四类数据源

### A. 市场行情
必须覆盖：
- 交易日历
- 指数行情
- 两市成交额
- 涨跌家数
- 涨跌停
- 个股日线
- 行业/概念板块
- 板块成交额
- 龙头/涨停梯队

统一接口：`MarketDataAdapter`

### B. 公司披露
必须覆盖：
- 公司公告
- 定期报告
- 业绩预告
- 重大订单
- 回购/增持/减持
- 并购重组
- 投资者关系活动记录

统一接口：`DisclosureAdapter`

### C. 政策/新闻
优先级：
1. 政府官网
2. 部委/监管机构
3. 交易所
4. 权威财经媒体
5. 券商与专业机构
6. 社交媒体/传闻

统一接口：`PolicyNewsAdapter`

### D. 产业数据
包括：
- 产品价格
- 库存
- 产能
- 稼动率
- 排产
- 交期
- 出货量
- 下游资本开支
- 产业链订单
- 进口/出口数据

统一接口：`IndustryDataAdapter`

---

## 2. 标准化字段

所有证据统一转换为：

```json
{
  "evidence_id": "",
  "trade_date": "",
  "entity_type": "theme|stock|industry",
  "entity_key": "",
  "evidence_level": "A|B|C|D",
  "evidence_type": "policy|announcement|earnings|order|price|capacity|media|rumor",
  "title": "",
  "source_name": "",
  "source_url": "",
  "published_at": "",
  "excerpt": "",
  "verified": true
}
```

---

## 3. 证据等级

A级：
公司公告、定期报告、官方政策、交易所、政府官网。

B级：
投资者关系、权威财经媒体、行业协会、公开产业数据。

C级：
券商研报、专业机构观点。

D级：
市场传闻、社交媒体、股吧。

D级不能支撑高兑现分。

---

## 4. 数据源冗余

建议关键字段至少两路来源：

行情：
主数据源 + 备用行情源

公告：
交易所/官方披露 + 聚合检索

政策：
官方来源优先 + 权威媒体补充

产业：
价格/库存数据库 + 行业协会/公司交流验证

---

## 5. 缓存

所有原始数据按：
`data/cache/YYYY-MM-DD/source_name/`

保存原始响应。

这样后续评分错误时，可以回溯当时到底拿到了什么数据。

---

## 6. Codex 不应该直接做什么

Codex 不应该直接负责：
- 计算大量逐笔行情
- 猜测缺失财务数据
- 把搜索摘要当事实
- 把不同数据源的同名字段直接拼接

数据层先标准化，Codex 再做：
归因、因果链、评分、阶段判断、变化检测、报告撰写。
