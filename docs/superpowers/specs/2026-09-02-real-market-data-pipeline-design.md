# A股复盘真实数据链路设计

## 1. 目标

将第一阶段复盘系统从“可使用演示数据展示功能”升级为“只使用真实市场数据生成正式分析”的生产链路。

系统必须做到：

- Tushare 作为核心市场数据主源。
- 腾讯、同花顺、交易所和巨潮资讯用于补充或交叉核验。
- 东方财富仅作为限定字段的应急降级源，并完整披露使用情况。
- 正式数据库、Dashboard 和 PDF 不展示模拟数据。
- 市场题材和个股名单由指定交易日的真实数据动态识别，不注入固定示例。
- 关键数据不完整时拒绝生成正式结论，不使用零值、前日值或模拟值填补。

本设计不包含券商连接、自动下单和实盘交易执行。

## 2. 已确认原则

### 2.1 数据真实性

正式分析只能使用可追溯的真实数据。每批数据至少记录：

- 数据源
- 接口或数据集标识
- 交易日期
- 抓取时间
- 原始响应位置或内容摘要
- 数据覆盖率
- 校验状态
- 是否为降级来源

模拟数据只能保留在自动化测试夹具中，不得写入生产数据库，不得出现在生产 Dashboard 或正式报告中。

### 2.2 动态分析

“AI 算力”“中际旭创”等名称仅是此前讨论中的示例，不属于固定配置。题材、龙头、容量中军、补涨和风险票必须从当日真实数据中产生。当天没有相应证据时，不得出现在结果中。

### 2.3 严格数据门禁

系统宁可拒绝生成正式报告，也不能用不完整数据制造确定性结论。门禁失败时只生成数据质量报告或带明显状态标识的盘中草稿。

## 3. 数据源策略

### 3.1 核心数据

以下数据以 Tushare 为主源，不允许由东方财富替代：

- 交易日历
- A股证券基础列表
- 个股日线基础行情
- 主要指数基础行情
- 复权因子
- 财务报表和标准财务指标

交易所公告、监管事实和公司正式披露以交易所、巨潮资讯为权威来源。

### 3.2 补充数据

腾讯和同花顺用于补充盘中行情、市场宽度、涨跌停、炸板、连板梯队、题材热度及相关短线情绪数据。补充数据必须保留来源，不能覆盖原始记录。

### 3.3 东方财富降级边界

当前述补充源失败或覆盖率不足时，东方财富可用于：

- 涨跌家数及市场宽度
- 涨停、跌停和炸板明细
- 连板梯队辅助核验
- 题材分类、板块热度及成分归属
- 其他不影响证券代码、交易日期和基础行情真实性的补充字段

每次降级必须记录：

- 使用原因
- 被替代的数据源
- 接口和抓取时间
- 使用字段
- 覆盖率
- 是否通过其他来源交叉验证

Dashboard 和 PDF 的数据质量区域必须显示“使用东方财富降级数据”。东方财富数据不能绕过严格门禁；覆盖率或一致性不足时仍不得生成正式报告。

## 4. 四层架构

### 4.1 原始数据层

各适配器只负责请求、响应保存和基础接口错误归类。原始响应先落盘，再进入标准化处理。原始文件按数据源、交易日期、接口和抓取批次组织，禁止静默修改。

### 4.2 标准化层

标准化层负责：

- 证券代码统一为 `ts_code`
- 日期和时间字段统一
- 金额、成交量、涨跌幅和比例单位统一
- 重复记录识别
- 股票范围和覆盖率校验
- 跨源一致性校验
- 冲突记录留存

多个来源冲突时不能静默覆盖。标准化记录保留选用值、候选值、选用理由和冲突状态。

### 4.3 分析层

分析层只能读取已完成标准化且通过门禁的数据快照。它负责市场情绪、题材周期、个股地位和交易纪律计算，并保存数据版本、规则版本、指标明细、结论和置信度。

### 4.4 展示层

Dashboard 和 PDF 读取同一个正式分析快照。生产界面移除“真实/模拟”切换，并展示报告状态、数据更新时间、门禁结果、整体置信度和降级来源。

## 5. 每日数据流程

1. 使用 Tushare 交易日历确认目标日期。非交易日停止采集，并返回最近交易日提示。
2. 拉取证券列表、全部A股日行情、主要指数和复权因子。
3. 核对应有证券数量、实际覆盖数量、重复代码、缺失代码和日期一致性。
4. 从个股原始行情重新计算成交额、涨跌家数等可复算市场指标。
5. 从腾讯和同花顺采集涨跌停、炸板、连板和题材补充数据。
6. 使用日行情重新校验涨跌停状态，无法确认的记录进入待核验集合。
7. 从交易所和巨潮资讯采集公告、监管信息和催化证据。
8. 必要时在限定字段范围内启用东方财富降级源。
9. 原始响应落盘，完成标准化、冲突记录和覆盖率统计。
10. 执行严格数据门禁。
11. 门禁通过后，以单个交易日事务写入正式数据库并运行分析。
12. 生成 Dashboard 快照和 PDF；门禁失败则只生成数据质量报告或盘中草稿。

同一交易日重复运行必须保持幂等。数据源更新后允许生成新版本，但不得覆盖历史正式版本及其来源记录。

## 6. 数据门禁

### 6.1 硬门禁

以下项目是正式报告的必要条件：

- 目标日期是已确认的交易日
- 证券范围有效且覆盖率达到配置阈值
- 全市场个股日行情完整且日期一致
- 主要指数行情完整
- 成交额、涨跌分布等市场宽度指标可复算
- 涨停、跌停、炸板和连板结构达到最低完整度
- 不存在会改变核心结论的未解决数据冲突

首版硬门禁采用以下默认阈值：

- 交易日历、交易日期和证券代码格式一致性：100%
- 目标日上市证券状态可解释率：不低于 99.5%；没有行情的证券必须能确认停牌、退市整理或其他合法状态
- 个股日行情关键字段完整率：不低于 99.5%
- 配置内主要指数行情完整率：100%
- 涨停、跌停和连板候选覆盖率：不低于 98%
- 补充源结果与日行情重算结果的差异：不超过两只股票或候选总数的 2%，取较大值
- 会改变市场阶段、题材前三名或个股地位的未解决关键冲突：0 个

覆盖率分母、排除规则和阈值必须集中配置并随规则版本保存。报告展示实际值、阈值和排除数量。适配器不能自行修改阈值；未来调整必须通过配置版本和回放测试。

### 6.2 增强数据

龙虎榜、资金流、公告催化等属于增强数据。增强数据缺失时可以生成正式报告，但相关模块必须降低置信度并说明缺失影响。

### 6.3 门禁结果

门禁结果分为：

- `PASSED`：允许生成正式复盘和 PDF
- `DRAFT_ONLY`：只允许生成有明显标识的盘中草稿
- `FAILED`：只生成数据质量报告

任何缺失数据不得由零值、默认值、前一交易日数据或模拟值填补。

## 7. 动态分析引擎

### 7.1 市场情绪仪表盘

输入包括涨跌家数、成交额、涨跌停、炸板率、连板高度、晋级率、昨日涨停反馈、指数强弱和市场宽度。

输出包括：

- 冰点、修复、主升、分歧、退潮之一
- 情绪温度
- 建议总仓位区间
- 判断依据
- 指标冲突
- 置信度

仓位区间是纪律提示，不是自动交易指令。

### 7.2 题材周期识别

综合题材涨停数量、成交额、扩散程度、连板结构、持续天数、核心股反馈和公开催化，输出题材强度排名，并标记为启动、发酵、主升、分歧、修复或退潮。

证据不足的概念只能进入观察题材，不能强行定义为市场主线。题材归因必须保存主归因、候选归因和证据来源。

### 7.3 个股地位识别

根据题材贡献、连板辨识度、成交容量、主动性、带动性、封板质量和历史地位，将候选股票分类为：

- 龙头
- 容量中军
- 低位补涨
- 中位股
- 孤立票
- 风险票

每个标签必须附指标和规则依据，不能只保存最终名称。

### 7.4 交易纪律熔断

数据门禁失败、情绪退潮、连续亏损、单日回撤超限或策略失效时，系统输出禁止开仓、降低仓位、只观察或暂停交易等纪律状态。第一阶段不连接券商，也不自动下单。

## 8. Dashboard 与 PDF

Dashboard 采用已确认的密集工作台风格：

- 顶部显示交易日期、报告状态、数据更新时间、门禁结果和整体置信度
- 第一屏显示市场温度、情绪阶段、建议仓位和核心市场指标
- 题材页面显示强度、周期、持续时间、扩散程度、核心梯队和催化依据
- 个股页面按六类地位展示，并提供分类依据
- 数据质量页面显示来源覆盖率、异常、冲突和降级记录

PDF 与 Dashboard 使用同一分析快照，固定包含：

1. 市场结论与仓位纪律
2. 核心指标和情绪阶段
3. 题材强度与周期
4. 个股地位及风险分类
5. 次日观察条件
6. 数据质量、降级来源和置信度说明

PDF 使用思源黑体和黑色正文。在不过度增加页数的前提下尽可能增大正文字号。东方财富降级信息集中展示在数据质量区域，避免在正文重复堆叠提示。

## 9. 错误处理

适配器错误统一归类为超时、限流、权限不足、空响应、字段变化、日期错位和内容不完整。系统应重试可恢复错误，但不得无限重试。重试耗尽后按数据重要性进入降级、草稿或失败状态。

单个交易日采用事务写入。任一正式写入步骤失败时整体回滚，防止半份数据进入生产数据库。错误日志不得输出 `TUSHARE_TOKEN` 等凭据。

## 10. 测试与验收

### 10.1 数据源测试

覆盖 Tushare、腾讯、同花顺、交易所、巨潮和东方财富降级接口的正常响应、超时、限流、空响应、字段变化和权限不足。

### 10.2 门禁测试

验证日行情缺失、证券数量不足、日期错位、重复代码、涨跌停数据不完整和关键冲突时，系统不会生成正式报告。

### 10.3 分析规则测试

使用固定的历史真实数据快照回放，确保相同数据版本和规则版本产生一致结果。验证题材和个股名称来自实际数据，而不是示例配置。

历史真实快照只能用于测试回放，不得伪装成目标交易日的实时采集结果，也不得写入生产数据库。

### 10.4 端到端测试

指定一个历史交易日，完成采集、原始数据落盘、标准化、门禁、分析、正式写入、Dashboard 和 PDF 全流程。验证重复运行幂等，且 Dashboard 与 PDF 内容一致。

### 10.5 视觉验收

检查桌面和移动视口中的遮挡、溢出和字号。渲染 PDF 页面，检查思源黑体嵌入、正文黑度、表格换行、分页和页数变化。

## 11. 配置与凭据

`TUSHARE_TOKEN` 通过环境变量或本地 `.env` 提供，不写入代码、数据库、报告或 Git。项目提供不含真实值的配置样例，并在启动时验证凭据是否存在。

Tushare 接口权限和积分可能影响可用数据。权限不足必须显示具体受影响的数据集，并由门禁决定是否允许继续，不能自动伪造数据。

## 12. 完成定义

满足以下条件后，本次真实数据链路改造完成：

- 生产 Dashboard 和正式数据库中不存在模拟记录
- 可为指定历史交易日完成真实数据全链路
- 硬门禁失败时不会生成正式复盘或正式 PDF
- 数据完整时能生成可追溯且一致的 Dashboard 和 PDF
- 题材和个股结果完全由当日数据动态产生
- 东方财富只在约定范围内降级使用，且完整披露
- 所有自动化测试和视觉验收通过
